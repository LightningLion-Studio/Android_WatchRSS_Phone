# Notes rendering and title contract

The title rule is identical on watch, mini and phone, including the hotfix.
It uses pinned Unicode 17.0.0 properties rather than platform dictionaries.

- Select the first nonempty CR/LF-delimited line, trimming the ECMA whitespace
  set (including BOM) on all runtimes.
- A word starts with a Unicode Letter or Number and retains following Letters,
  Numbers, Marks and join controls. A pure Han run longer than four code points
  uses two-code-point words. This is a deterministic word-run rule, not locale
  dictionary segmentation. The selected source spacing and punctuation survive.
- Select three words; no-word lines use the whole line. Extend selection edges
  to source grapheme boundaries. Keep at most 80 code points and retreat to the
  last complete extended grapheme. Do not count 80 graphemes instead.
- No NFC/NFD normalization is performed. Supplementary letters count as words.
- Graphemes follow UAX #29, Unicode 17 (including Hangul, Indic conjuncts, emoji
  ZWJ, variation selectors, modifiers and regional-indicator pairs).

The word, grapheme and script properties are generated from:
https://www.unicode.org/Public/17.0.0/ucd/UnicodeData.txt
https://www.unicode.org/Public/17.0.0/ucd/Scripts.txt
https://www.unicode.org/Public/17.0.0/ucd/auxiliary/GraphemeBreakProperty.txt
https://www.unicode.org/Public/17.0.0/ucd/emoji/emoji-data.txt
https://www.unicode.org/Public/17.0.0/ucd/DerivedCoreProperties.txt
Conformance cases: auxiliary/GraphemeBreakTest.txt from the same directory.
Source hashes are in notes-unicode-sources.json. The license is in
notes-unicode-LICENSE.txt. UAX #29: https://www.unicode.org/reports/tr29/

Generator: the watch repository's scripts/generate-notes-unicode.py takes a
folder with those six input files (flat basenames). It writes the raw varint
range table and a zlib representation. The raw decoded SHA-256 must remain
2394d0ad59d424e4dfeed29e8ce427e8e1576f1781e8351368272fdb03a9385b.
Watch JSON and phone's TITLE_UNICODE_DATA use the raw base64 table. Mini uses the
same table compressed with zlib through its existing fflate vendor module.
All runtimes test the same 36 title vectors and the official 766 grapheme cases
at all 2756 code-point cut positions.

## Mini source and build layout

Readable sources are dev/notes-render/{codec.js,state.js,title.ts,title-unicode.ts}.
Run `node scripts/build-notes-render.mjs` to regenerate miniprogram/lib modules.
Run it with `--check` to verify the checked-in generated bytes.
The existing state source has no new behavior in r3; it is compacted to retain
the unchanged 2,350,000-byte main source budget. Do not edit generated modules.
Local identifiers are compacted; object property names and exports are retained.

The HTML writer emits only approved complete tags and attributes. It escapes
all unmatched '<' text, drops event attributes and active URL schemes, checks
rewritten image URLs, removes active elements with their content and rechecks
the final concatenated projection. Incomplete tags cannot capture later code
paragraphs. Wire originals and title-only saves retain their existing behavior.
The allowlist is in the readable codec source; it is not a browser DOM API.

## Watch code blocks

Only space/tab-only closing fence lines close a block. Backtick info strings
cannot contain backticks. Four-space and tab-indented code is literal and does
not resolve images. Reading entries retain code text and source anchors.
The frozen Kotlin preview fixture is kept unchanged; one old indented-image
expectation is explicitly replaced by the corrected r3 product expectation.

RNR-07 review tests were policy controls for the old code-point-only behavior.
Their expected strings now assert the authorized whole-grapheme policy. The
RNR-01 through RNR-06 regression assertions remain intact.
